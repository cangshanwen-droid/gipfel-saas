## 二、最终审核结果

### 🔴 审核发现（三路并行审计，全部修复闭环）

| 编号 | 发现 | 严重度 | 修复 | 验证 |
|------|------|:--:|------|------|
| SEC-P0 | **资金桥越权**：`/api/stock/fund` 用请求体 username 而非 JWT 身份，任意登录用户可操作他人区域账户资金 | P0 | JWT 身份绑定（非 admin 只能操作自己） | ✅ 实测 403 拦截 |
| BIZ-H1 | **审批/编辑无角色校验**：rep 绕过前端可直接调 API 审批/创建/编辑合同 | 高 | create/update/approve 限 admin/operator | ✅ 实测 403 + rep 只读正常 |
| BIZ-H2 | **数据隔离缺失**：rep 可拉取全部合同（云端无 org 过滤）+ **公司 org_id 从未写回**（公司与组织关联断裂——隔离与资金映射的地基） | 高 | 列表/详情按 org 强制过滤 + 建公司补 org_id + 存量迁移 | ✅ 实测 rep 只见本公司、跨公司 403 |
| BIZ-H3 | **编辑投资/拨款合同金额归零**：前端编辑只传 7 字段，云端重算 total_cost=0 → 激活不入账（桌面端有继承修复，云端缺）+ **金额口径分叉**（云端 0 算显式 vs 桌面端 0 走推算）+ **带 items 编辑必 500**（`_changed_fields` 对 dict 调 model_dump） | 高 | 编辑继承旧明细显式金额 + `>0` 才显式口径统一 + dict 兼容 | ✅ 实测编辑后 800000 保留 + 激活入账 + pytest 13/13 |
| ENG-P0 | PEP 604 语法（`int\|None`）| P0 | **确认误报**——仅未部署的 main.py 有，线上 stock_mini.py 与 gipfel-saas 零残留 | ✅ grep 实证 |
| ENG-P2 | async 函数内同步 urllib 调用 | P2 | 影响小（单用户场景），记录不修 | 📝 已记录 |
| ENG-P2 | stock-api 无自动化测试 | P2 | **已补**：`tests/test_smoke.py` 4 项冒烟 | ✅ 4/4 通过 |

### 此前已修复的重大问题（多轮实测发现）

- **并发合同编号竞态** → 顺序号+随机后缀+重试（12/12 并发全成功）
- **资金并发丢更新** → 原子 UPDATE（2 笔并发扣款精确）
- **合同入账 ORM 读改写** → 原子 UPDATE（新增，同类 bug 排查修复）
- **fetch 全局遮蔽栈溢出** → window.fetch 显式化
- **sql.js checkIntegrity 误判** → PRAGMA integrity_check
- **SECRET_KEY 默认值** → 强随机入 systemd
- **跨库资金一致性** → 资金桥（幂等 DB 级唯一索引 + 补偿回滚）
- **资金桥并发同 key 双扣** → DB 级幂等（5 并发只扣一次）

## 五、用户使用指南（速查）

- **登录**：admin / admin123（统一账号，软件端与股票端同一账号同一密码）
- **股票**：登录软件后直接进股票面板，无需重复登录（iframe 免登录）
- **主席（admin/operator）**：可操作**本公司股票账户**买卖（资金与区域基建账户**完全分开**，每公司独立 10 万）
- **代表（rep）**：**只读**——可见本公司可用资产/持仓/市值（与主席看到的一致），**不能买卖**（403）
- **运营商（operator）**：合同创建/编辑/审批 + 本公司股票买卖
- **管理员（admin）**：全部 + 用户管理 + 股票账户总览（公司维度）
- **数据安全**：每日 04:30 自动备份；断网 10s 超时提示不丢数据
